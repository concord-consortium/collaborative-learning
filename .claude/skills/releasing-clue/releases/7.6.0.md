## Background facts (discovered)

- `package.json` on `master` says `4.3.0`; the real version only lands on the
  release branch via `npm version`. Release branches: `origin/v7.5.x` has a single
  `7.5.0` commit on top of master, and the tag `v7.5.0` points to it.
- Deploys are S3 copies: the tag build lives at
  `s3://models-resources/collaborative-learning/version/<tag>/`. The
  `Release Staging` / `Release Production` workflows (`workflow_dispatch`, input
  `version` = git tag) copy `index-top.html` for the app, `editor/`, `authoring/`
  and `authoring-iframe/` to `staging.html` / `index.html`, then notify Rollbar.
- GitHub release format (from v7.5.0): title is the bare version (`7.5.0`), body has
  sections `### ✨ Features & Improvements:`, `### 🐞 Bug Fixes:`,
  `### 🛠 Under the Hood:` with `- **CLUE-NNN:** summary` lines.
- dev-templates scripts live in `~/Development/dev-templates/scripts`
  (`npm run release-notes-jira`, `unlinked-prs`, ...), with tokens in `scripts/.env`.

### 2b. (new) Firebase deployables and external dependencies — IN PROGRESS

Not in the dev-templates doc. A release has to coordinate:
- Firebase (projects in `.firebaserc`: `staging` = collaborative-learning-staging,
  `production` = collaborative-learning-ec215): Firestore rules, RTDB rules
  (`database.rules.json`), Firestore indexes, functions (codebases `functions-v1`,
  `functions-v2`, `authoring-api` in `firebase.json`; `functions-v2` imports `shared/`)
- External: portal APIs, token-service, report-service, curriculum units (unit
  config compatibility), ForeverLearning backend.
Goal: know what must be deployed, whether it's forward compatible (can go before
the client), and whether staging/production already match the code. For rules
changes, a UI test plan (portal launch; which unit enables the feature).

How to check what changed: `git diff --name-status v7.5.0 origin/master -- firestore.rules
database.rules.json firestore.indexes.json firebase.json functions-v1 functions-v2
authoring-api shared`. For 7.6.0: firestore.rules + firestore.indexes.json + functions-v2
+ shared changed; database.rules.json, functions-v1, authoring-api did not.

How to read deployed state (read-only):
- Functions: `firebase functions:list --project <env> --json`. Names/codebase/runtime,
  `labels["firebase-functions-hash"]`, and `source.storageSource.generation` which is a
  microsecond timestamp = deploy time (not available for gcfv1 functions).
  Compare deploy times against `git log --first-parent -- functions-v2 shared`.
- Indexes: `firebase firestore:indexes --project <env>`. Deployed output adds an implicit
  `__name__` field to every index — strip it before diffing against the code.
- Rules: Firebase Rules API `releases/cloud.firestore` → ruleset source; RTDB
  `https://<db>.firebaseio.com/.settings/rules.json`. Needs `gcloud auth print-access-token`
  (gcloud needed re-login — `gcloud auth login`). RTDB instances:
  staging `collaborative-learning-staging-default-rtdb`, prod `collaborative-learning-ec215`.
